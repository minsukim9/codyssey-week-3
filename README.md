# Mini NPU Simulator

2차원 배열로 표현된 패턴과 필터의 MAC(Multiply-Accumulate) 연산을 구현하고,
Cross와 X 패턴을 판별하는 Python 콘솔 프로그램입니다.

3x3 사용자 입력 모드와 `data.json` 분석 모드를 지원하며,
배열 크기에 따른 MAC 연산 시간과 연산 횟수를 비교할 수 있습니다.

## 개발 환경

- Python 3.8 이상
- Python 표준 라이브러리 사용
- 외부 라이브러리 사용 없음

## 실행 방법

프로젝트 루트 디렉토리에서 다음 명령어를 실행합니다.

```bash
python3 main.py
```

프로그램 실행 후 두 가지 모드 중 하나를 선택할 수 있습니다.

```text
=== Mini NPU Simulator ===

[모드 선택]

1. 사용자 입력 (3x3)
2. data.json 분석
선택:
```

### 1. 사용자 입력 모드

3x3 필터 A와 필터 B를 각각 입력한 뒤,
판별할 3x3 패턴을 입력합니다.

각 행은 숫자 3개를 공백으로 구분하여 입력합니다.

```text
0 1 0
1 1 1
0 1 0
```

입력된 패턴과 두 필터의 MAC 점수를 계산하고,
점수 비교 결과에 따라 A, B 또는 판정 불가를 출력합니다.

### 2. data.json 분석 모드

프로젝트 루트 디렉토리의 `data.json` 파일을 읽어
5x5, 13x13, 25x25 필터와 패턴을 분석합니다.

각 패턴에 대해 다음 내용을 출력합니다.

- Cross MAC 점수
- X MAC 점수
- Cross / X / UNDECIDED 판정
- expected와 비교한 PASS / FAIL 결과
- 크기별 MAC 평균 연산 시간
- 전체 테스트 결과 요약

## 구현 요약

### MAC 연산

패턴과 필터의 동일한 위치에 있는 값을 곱한 뒤,
모든 결과를 누적하여 하나의 점수를 계산합니다.

N x N 배열에서는 모든 위치를 한 번씩 확인하므로
총 N²번의 곱셈 및 누적 연산을 수행합니다.

### 라벨 정규화

`data.json`에서 사용하는 라벨과 프로그램 내부에서 사용하는 라벨이 다르기 때문에
다음과 같이 표준화합니다.

```text
cross → Cross
+     → Cross
x     → X
```

프로그램 내부의 표준 라벨은 `Cross`, `X` 두 가지를 사용합니다.

### 동점 처리

MAC 연산 결과는 실수 연산을 포함하기 때문에
부동소수점 표현 오차가 발생할 수 있습니다.

따라서 단순히 두 점수가 같은지 비교하지 않고 다음 허용오차를 사용합니다.

```text
epsilon = 1e-9
```

두 점수 차이의 절댓값이 epsilon보다 작으면
두 점수를 같은 값으로 판단하고 `UNDECIDED` 처리합니다.

## 결과 리포트

### data.json 분석 결과

현재 제공된 `data.json`을 분석한 결과는 다음과 같습니다.

```text
총 테스트: 6개
통과: 3개
실패: 3개
```

실패 케이스는 다음과 같습니다.

```text
size_5_1  : UNDECIDED
size_13_2 : UNDECIDED
size_25_1 : UNDECIDED
```

### 실패 원인 분석

`size_5_1`의 Cross 점수는 0.9이고 X 점수는 0.8999999999999999로 계산되었습니다.

두 값만 보면 Cross 점수가 조금 더 큰 것처럼 보이지만,
두 점수의 차이는 epsilon인 `1e-9`보다 작습니다.

따라서 두 점수를 동일한 점수로 판단하여 `UNDECIDED` 처리했습니다.

`size_13_2` 역시 Cross 점수 7.499999999999997과 X 점수 7.5의 차이가
epsilon보다 작기 때문에 `UNDECIDED`로 판정되었습니다.

`size_25_1`의 Cross 점수 4.9와 X 점수 4.899999999999999 역시
부동소수점 표현 차이만 존재하므로 `UNDECIDED`로 판정되었습니다.

이 세 케이스의 expected 값은 각각 X 또는 Cross이기 때문에
`UNDECIDED` 결과와 일치하지 않아 FAIL 처리되었습니다.

이는 MAC 연산 로직의 오류가 아니라,
부동소수점 오차를 고려한 epsilon 비교 정책에 따른 결과입니다.

단순히 `>` 연산자로 두 점수를 비교했다면 아주 작은 표현 오차에 의해
Cross 또는 X 중 하나가 선택될 수 있으므로 잘못된 판정으로 이어질 수 있습니다.

따라서 허용오차를 적용하여 실제로 동일하다고 볼 수 있는 점수를
동점으로 처리하는 것이 더 안정적인 비교 방법이라고 판단했습니다.

또한 JSON 패턴과 필터의 크기 또는 스키마가 올바르지 않은 경우
프로그램 전체를 종료하지 않고 해당 케이스만 FAIL 처리하도록 구성했습니다.

이를 통해 데이터 문제, 판정 로직 문제, 수치 비교 문제를 분리하여
실패 원인을 확인할 수 있도록 구현했습니다.

## 성능 분석

각 크기의 MAC 연산을 10회 반복한 뒤 평균 실행 시간을 측정했습니다.

시간 측정에는 `time.perf_counter()`를 사용했으며,
파일 입출력이나 콘솔 출력 시간은 제외하고 MAC 함수 호출 구간을 측정했습니다.

| 크기 | 평균 시간(ms) | 연산 횟수 |
|---|---:|---:|
| 3x3 | 0.000504 | 9 |
| 5x5 | 0.000908 | 25 |
| 13x13 | 0.004583 | 169 |
| 25x25 | 0.015779 | 625 |

MAC 연산은 N x N 배열의 모든 위치를 순회합니다.

따라서 배열 한 변의 길이가 N일 때 총 N²개의 원소에 접근합니다.

3x3에서는 9번, 5x5에서는 25번,
13x13에서는 169번, 25x25에서는 625번의 연산이 필요합니다.

N이 증가할수록 처리해야 하는 데이터 수가 N²에 비례하여 증가하기 때문에
MAC 연산의 시간 복잡도는 `O(N²)`입니다.

실제 측정 시간은 운영체제의 스케줄링이나 현재 시스템 상태 등에 따라
실행할 때마다 조금씩 달라질 수 있습니다.

하지만 배열의 크기가 증가할수록 수행해야 하는 MAC 연산 횟수가
9 → 25 → 169 → 625로 증가한다는 점은 동일합니다.

이를 통해 입력 크기가 커질수록 MAC 연산에 필요한 작업량도
제곱 비율로 증가한다는 것을 확인할 수 있습니다.
